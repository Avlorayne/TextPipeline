# 错误处理

本文定义标记解析失败时的处理目标、错误分类和恢复边界。语法见 `Lexical Structure`，上下文合法性见 `Contextual Constraints.md`，成功标签的运行时语义见 `Semantics.md`。

## E1. 基本原则

标记解析采用**HTML 风格的局部容错**：单个候选标签失败不得中止整段文本的解析或后续 `TextPipeline` 处理，也不得使外围块原子性回退。

解析失败的候选标签：

- 不得创建标签节点；
- 不得绑定处理实例；
- 不得形成效果范围；
- 不得依 `Semantics.md` 的 S5 收束；
- 必须依 E4 在标签边界恢复，而不是创建效果范围。

只有完全不能构成标签起始的 `<` 才作为普通文本字符保留。已识别但失败的标签会按 E4 被忽略；其后的文本及后续标签仍继续解析。

## E2. 错误分类

| 类别 | 例子 | 结果 |
|---|---|---|
| 词法错误 | 大写标识符、非法数字、未闭合字符串 | 按 E4 容错 |
| 句法错误 | 缺少 `=`、逗号或 `>`，或在单值形式中混入具名参数 | 按 E4 容错 |
| 上下文错误 | 结束标签不匹配、重复属性、未知属性或函数，或单值形式无法唯一绑定 | 按 E4 或 E5 容错 |
| 契约错误 | 属性/参数类型不匹配、标签实现的值域校验失败 | 按 E4 容错 |

实现可以记录诊断信息；诊断不得改变“失败即放行”的结果。

## E3. 诊断信息

每个诊断至少应包含：

- 错误类别；
- 原始输入中的起始字符索引；
- 可选的结束字符索引；
- 面向作者的错误说明。

字符索引必须指向收束前的原始输入，不能使用正式文本中的索引；否则标签收束会使错误位置不稳定。

建议的错误说明：

```text
[上下文错误] index 12: 结束标签 </bar> 与开始标签 <foo> 不匹配。
[契约错误] index 8: 标签 <wave> 不接受属性 "unknown"。
```

## E4. 恢复边界

“原样放行”已经确定；尚需确定一次失败究竟覆盖哪些字符。该决定会影响失败标签内部是否还能识别到后续合法标签。

采用**HTML 风格的标签级恢复**。解析器不将已识别但失败的完整标签回退为普通文本；它丢弃该标签字面量，并从标签结束位置继续扫描。

```html
<bad : x = >before<wave>ok</wave>
```

`<bad : x = >` 被忽略，后续文本 `before` 与 `<wave>ok</wave>` 仍继续解析；`wave` 仍可生效。

恢复规则如下：

1. 当 `<` 后的字符不能构成 `block-start`、`single-markup` 或 `block-end` 的起始时，`<` 作为普通文本字符输出，随后从其后一个字符继续扫描。
2. 当解析器已识别到一个候选标签起始，但该标签在词法、句法、契约或值校验中失败时，解析器必须跳过该候选标签至其对应的 `>`；位于 `quoted-string` 内的 `>` 不构成标签边界。若输入结束前不存在对应的 `>`，则跳过至输入结束。
3. 被跳过的候选标签不得进入正式文本，不得创建节点，也不得产生效果；候选标签后的文本和后续候选标签必须继续解析。

这对应 HTML 的容错原则：错误不回退已经识别的标签边界，不阻断后续 token 的形成。块结束标签的特殊栈式恢复规则见 E5。

## E5. 块不匹配与缺失结束标签

块结构采用 HTML 风格的栈式恢复。解析器维护未闭合块的栈；结束标签到来时，从栈顶向下寻找同名开始标签。

```html
<foo>text</bar>
<foo>text
</foo>
```

恢复规则如下：

1. 若找到同名开始标签，位于它之上的所有未闭合块必须先被**隐式关闭**，再关闭该同名块。
2. 若栈中不存在同名开始标签，该结束标签是孤立结束标签；它必须被忽略，不创建节点、效果范围或正式文本字符。
3. 输入结束时，栈中仍未闭合的块必须按由内到外的顺序隐式关闭。

```html
<foo><bar>text</foo>
```

等价的树形闭合结果为：

```html
<foo><bar>text</bar></foo>
```

```html
<foo>text</bar>
```

`</bar>` 没有可匹配的开始标签，因而被忽略；`foo` 在输入结束时隐式关闭。

块经隐式关闭后，其内部已成功解析的标签和效果范围必须保留并生效。E5 仅处理结构性结束标签，不改变 E4 对词法、句法、契约或值校验失败标签的标签级忽略规则。

## E6. 错误后继续解析

恢复后，解析器必须继续尝试识别后续候选标签。为保证进度，任意一次失败恢复都必须消耗至少一个输入字符；不得在同一字符位置反复重试而陷入循环。
